🧠 RAG Simulator

Understand Retrieval Augmented Generation step-by-step. This simulator lets you see how documents become chunks and vectors, how a query retrieves relevant information, and how that information is passed to an LLM to generate a grounded answer.

STEP 1

📄 Add a Document

In a real RAG system this could be a PDF, webpage, database record, Word document, etc.
STEP 2

✂️ Chunking

Large documents are split into smaller pieces so that relevant information can be retrieved later.
Click Process Document to create chunks.
STEP 3

🔢 Embeddings

Each chunk is transformed into a numerical representation capturing its semantic meaning.
Embeddings will appear here after processing the document.
STEP 4

🗄️ Vector Database

The embeddings are stored alongside their original text and metadata.
Vector database is empty.
STEP 5

🔎 User Query

The user's question is also converted into an embedding.
STEP 6

🎯 Retrieval

The query vector is compared with document vectors. Higher similarity means the chunk is more relevant.
Run a query to see retrieval results.
Cosine Similarity = (A · B) / (||A|| × ||B||)
STEP 7

🧩 Augmentation — The Missing Piece

This is where RAG goes beyond simple vector search. The retrieved chunks are inserted into the prompt sent to the LLM.
The augmented prompt will appear here.
STEP 8

🤖 Generation

The LLM receives the user's question plus the retrieved context and generates a grounded response.
Run RAG to generate an answer.
THE COMPLETE RAG PIPELINE

🚀 Put Everything Together

1. Document
Raw information is provided to the system.
2. Chunking
The document is divided into smaller chunks.
3. Embedding
Each chunk is converted into a vector representing its meaning.
4. Vector Database
Chunk vectors are stored for efficient similarity search.
5. Query Embedding
The user's question is converted into the same vector space.
6. Retrieval
Similarity search finds the most relevant chunks.
7. Augmentation
Retrieved chunks are added to the LLM prompt as context.
8. Generation
The LLM uses the question + retrieved context to generate the answer.
This simulator uses simplified local embeddings and a rule-based answer generator. Its purpose is to visualize the RAG architecture, not reproduce a production embedding model.
